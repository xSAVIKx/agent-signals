Test your reader against the corpus

A reader is the function of your tool that gets the bytes of a screen and gives a state. This page shows how to run it against each screen of the corpus.

The corpus holds no code that your tool runs. Each tool keeps its own reader. Choose one of three ways to load the screens:

  • Go: the library agentsignals
  • Python: the package agent_signals
  • Other languages: the files

Go

  1. Add the library. It embeds the corpus, so the test needs no file and no network.

    go get github.com/xSAVIKx/agent-signals/go@v0.20.0

  2. Write one table test.

    func TestReader(t *testing.T) {
	screens, err := agentsignals.ScreensFor("claude")
	if err != nil {
		t.Fatal(err)
	}
	for _, s := range screens {
		t.Run(s.Slug, func(t *testing.T) {
			if s.KnownFalsePositive {
				t.Skip(s.KnownFalsePositiveReason)
			}
			if got := myReader(s.Bytes); got != s.Expect.State {
				t.Errorf("got %s, want %s", got, s.Expect.State)
			}
		})
	}
}

  3. Run go test ./.... The test passes when each screen gives its expected state.

Read the guide to the Go library

Python

  1. Install the package from a release tag. It needs Python 3.11 or later.

    pip install "agent-signals @ git+https://github.com/xSAVIKx/agent-signals@python-v0.14.0#subdirectory=python"

  2. Write one test with the pytest helper.

    import pytest
import agent_signals
from agent_signals.testing import parametrize_screens


@parametrize_screens("claude")
def test_reader(screen: agent_signals.Screen) -> None:
    if screen.known_false_positive:
        pytest.skip(screen.known_false_positive_reason)
    assert my_reader(screen.bytes) == screen.expect.state, screen.id

  3. Run pytest. The test passes when each screen gives its expected state.

Read the guide to the Python library

Other languages: the files

  1. Pin a corpus release tag, for example corpus-v0.26.0.
  2. Copy corpus/, schema/ and facts/ from that tag into your tree.
  3. For each .screen file, give the exact bytes to your reader.
  4. Compare the result with expect.state in the .yaml file beside it.

A program can also read corpus.json. It lists each screen with its fields and the URLs of its two files.

Four rules for a correct test

Give the exact bytes
Do not trim a line, and do not change a line ending. A .screen file holds the output of tmux capture-pane -p.
Prove IDLE
A reader must not give IDLE because no other rule matched. A tool types into an idle box.
Send no key to UNKNOWN
A screen that the reader cannot read is UNKNOWN.
Read the reason of a known false positive
2 screens have an expected state that is wrong on purpose. Read the reason before you skip the screen or change your reader.

When a test fails

What to read for each kind of failure
The test showsRead
A wrong state for one screenThe page of that screen: the text, the expected result, and the facts that it names.
A wrong state for each screen of one agent versionThe verified versions of that agent on the corpus page.
A new failure after you move the pinThe changelog of the corpus. It names each new screen.
A screen of your agent that the corpus does not haveThe task "Run the kit". It tells how to send a measurement.
